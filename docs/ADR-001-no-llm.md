# ADR-001. Генеративную модель не подключаем

**Статус:** принято.

**Решение.** Ни генеративной LLM, ни её API. Вопросы разбираются нормализацией, нечётким сопоставлением
(`rapidfuzz`) и кодом. Неуверенный разбор — `no_answer`.

**Почему.**
- Вопросов четыре шаблона, а автопроверка сравнивает `value`, `answerable` и `sources` точным совпадением.
  Стохастический ответ модели здесь только вредит; текст `answer` в автопроверке не участвует.
- Внешние API запрещены. Локальная модель 1–3B на CPU ноутбука даёт секунды на вопрос,
  тяжело запускается у проверяющих, и её ответ нельзя гарантировать детерминированным.
- Опасность не в том, что модель не поймёт вопрос, а в том, что поймёт «по-своему»:
  ответит на вопрос про стоимость или стипендию из памяти, а п. 2.4 это запрещает.

**Что делаем вместо.** Нормализация (регистр, `ё`, кавычки, пунктуация), `rapidfuzz` по каноническим
формулировкам намерений с запасом над вторым кандидатом, якоря-слова против ложных срабатываний.
Опционально и выключено по умолчанию: маленький энкодер только для выбора одного из четырёх намерений.

**Что отвечать жюри на «почему без LLM».** Задача закрытая, ответы должны быть воспроизводимыми и со
ссылками на пункты; генеративная модель добавляет риск галлюцинации без выигрыша по метрикам.
