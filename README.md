# Онлайн-деканат — цифровой секретарь

Проект III Межрегионального хакатона **UmirHack**, кейс «Онлайн-деканат» от **ЦентрИнвест**.

Студент загружает фото или PDF документа и задаёт вопрос. Система распознаёт текст, извлекает поля
документа, проверяет их по Положению и отвечает **со ссылкой на конкретный пункт**. Если ответа в
Положении нет (стоимость обучения, стипендия и т. п.), система честно говорит об этом и направляет в деканат.

- Работает **полностью офлайн**, без внешних API.
- **Без генеративной LLM**: ответы детерминированы и воспроизводимы (см. [ADR-001](docs/ADR-001-no-llm.md)).
- Запуск одной командой через Docker Compose.

## Возможности

**Поддерживаемые документы**

| `doc_type` | Документ | Извлекаемые поля |
|---|---|---|
| `study_certificate` | Справка об обучении | ФИО, вуз, программа, форма обучения, даты начала и окончания, номер, дата выдачи, подпись, печать |
| `academic_leave_application` | Заявление на академический отпуск | ФИО, группа, курс, причина, даты отпуска, дата заявления, подпись |
| `internship_certificate` | Справка о практике | ФИО, организация, даты практики, руководитель, оценка, номер, дата выдачи, подпись, печать |

**Типы вопросов**

| Вопрос | Что делает система |
|---|---|
| «Содержит ли документ все обязательные сведения?» | Проверяет полноту по Положению, перечисляет недостающие поля и пункты |
| «Укажи значение поля …» | Возвращает значение поля (даты в ISO) |
| «Кто принимает окончательное решение?» | Отвечает по п. 1.3 Положения |
| Вопросы вне Положения (стоимость, стипендия) | `no_answer`: честный отказ, без выдумывания |
| Перевод / восстановление / отчисление | Ответ по п. 3.5 Положения |

**Веб-интерфейс**

- Загрузка до 10 файлов за раз (JPG, PNG, WEBP, PDF); формат проверяется по содержимому, а не по расширению.
- Очередь задач с прогрессом, распознанный текст, поля и ответ с источником.
- Без регистрации: каждый посетитель получает случайный код сессии и видит только свои задачи.
- Светлая и тёмная темы, корректное отображение в Safari и macOS.
- Задачи и файлы старше часа удаляются автоматически; в лог не пишутся персональные данные.

## Технологии

### Распознавание документов (ML)

| Технология | Назначение |
|---|---|
| **PaddleOCR 3.7** (PP-OCRv5) + **PaddlePaddle 3.2.2** | Распознавание печатного текста на CPU. Детектор `PP-OCRv5_mobile_det`, русская модель распознавания `eslav_PP-OCRv5_mobile_rec`, автоповорот листа |
| **TrOCR** `kazars24/trocr-base-handwritten-ru` (**PyTorch** + **Hugging Face Transformers**) | Дочитывание рукописных строк, в которых Paddle не уверен (включается `USE_HANDWRITING=1`) |
| **OpenCV** | Предобработка изображения, поиск подписи и печати |
| **Pillow**, **NumPy** | Загрузка, проверка и обработка изображений |
| **pypdfium2** | Растеризация PDF в PNG (300 dpi, до 3 страниц) |

### Логика ответов

| Технология | Назначение |
|---|---|
| **RapidFuzz** | Нечёткое сопоставление: определение типа вопроса (роутер намерений) и исправление ошибок OCR в значениях полей |
| Правила на Python | База знаний Положения: обязательные поля по пунктам, проверка полноты, ответы со ссылками `rule:X.Y` и `field:…` |

Генеративные модели (LLM) намеренно не используются: задача закрытая, автопроверка сравнивает ответы
точным совпадением, а LLM добавляет риск галлюцинаций. Подробности: [docs/ADR-001-no-llm.md](docs/ADR-001-no-llm.md).

### Бэкенд

| Технология | Назначение |
|---|---|
| **Python 3.11** (поддерживается 3.9–3.13) | Язык проекта |
| **FastAPI** + **Uvicorn** | REST API, автодокументация Swagger (`/docs`) |
| **python-multipart** | Приём загружаемых файлов |
| **SQLite** (`sqlite3`) | Хранение задач и их результатов |
| `ThreadPoolExecutor`, `asyncio` | Фоновая очередь распознавания, прогрев моделей при старте, периодическая очистка |
| `logging` (RotatingFileHandler) | Логи в консоль и `data/logs/app.log` с ротацией |

### Фронтенд

| Технология | Назначение |
|---|---|
| **Streamlit ≥ 1.46** | Веб-интерфейс |
| **Requests** | Обращения к API бэкенда |
| Собственный CSS, шрифты **Unbounded** и **Manrope** (WOFF2, встроены локально) | Оформление, светлая и тёмная темы, работа без интернета |

### Инфраструктура и качество

| Технология | Назначение |
|---|---|
| **Docker** (multi-stage кэш, BuildKit) + **Docker Compose** | Два контейнера (бэкенд с ML и UI), модели «запекаются» в образ, healthcheck по готовности моделей |
| **pytest** | Модульные и интеграционные тесты (153 теста) |
| `evaluate.py`, `tools/run_batch.py` | Eval-стенд: метрики на открытом наборе организаторов, отчёт об ошибках по полям |
| `tools/degrade*.py`, **matplotlib** (опционально) | Устойчивость к плохим снимкам: порча изображений и кривая точности |
| **pyarrow** (опционально) | Прогон OCR на бенчмарке MWS-Vision-Bench |

## Архитектура

```
 ┌────────────────────┐   HTTP    ┌──────────────────────────── backend (FastAPI) ───────────────────────────┐
 │  UI (Streamlit)    │ ────────▶ │ main.py ──▶ jobs.py (очередь, SQLite) ──▶ pipeline.py                    │
 │  ui/app.py         │ ◀──────── │                                            │                             │
 └────────────────────┘  polling  │                     ┌──────────────────────┴──────────────────┐          │
                                  │                     ▼                                         ▼          │
                                  │   extract_fields: backend/ocr                 answer_question: backend/knowledge
                                  │   intake → preprocess → PaddleOCR              router (RapidFuzz) → правила
                                  │   (→ TrOCR) → text → fields + marks            Положения → ответ + sources │
                                  └──────────────────────────────────────────────────────────────────────────┘
```

1. **Приём файла** (`backend/main.py`): проверка формата по содержимому, PDF → PNG (`backend/pdf.py`), постановка в очередь.
2. **OCR** (`backend/ocr`): предобработка, PaddleOCR, при необходимости TrOCR для рукописи, склейка строк и исправление
   латиницы в кириллице.
3. **Поля** (`backend/ocr/fields.py`, `marks.py`): извлечение значений по подписям полей, нормализация дат в ISO,
   поиск подписи и печати.
4. **Ответ** (`backend/knowledge`): роутер определяет тип вопроса, правила Положения формируют ответ со списком
   источников. Формат ответа: `status`, `message`, `sources`, `answerable`, `value`, `missing_fields`.

## Быстрый старт (Docker)

Требуется Docker Desktop (или Docker Engine) с Compose v2.

```bash
cp .env.example .env
docker compose up --build
```

Когда модели загрузятся, в консоли появится адрес. Откройте **http://localhost:8501**.

- Модели скачиваются **при сборке образа**, поэтому контейнер стартует без интернета.
- UI запускается только после того, как бэкенд сообщит `ready: true`.
- Данные (база, загрузки, логи) хранятся в томе `deans_data`.
- Облегчённый образ без TrOCR и PyTorch: `WITH_HANDWRITING=0` в `.env`, затем пересборка.

## Локальный запуск без Docker

Нужен 64-битный Python 3.9–3.13 и процессор с поддержкой AVX.

```bash
python -m venv .venv
```

Активация: `.venv\Scripts\activate` (Windows) или `source .venv/bin/activate` (macOS, Linux).

```bash
pip install -r requirements.backend.txt -r requirements.ui.txt
```

Запуск в двух терминалах (в каждом активируйте окружение), сначала бэкенд:
терминал 1:
```bash
uvicorn backend.main:app --no-access-log
```
терминал 2:
```bash
streamlit run ui/app.py
```

- Интерфейс: http://localhost:8501
- Проверка бэкенда: http://127.0.0.1:8000/health (`ready: false`, пока грузятся модели, затем `true`)
- Документация API: http://127.0.0.1:8000/docs
- При первом запуске модели скачиваются автоматически (~100 МБ Paddle в `~/.paddlex`, TrOCR в `~/.cache/huggingface`).
- Если порт 8000 занят, запустите бэкенд с `--port 8001` и задайте `API_URL=http://127.0.0.1:8001` для UI.
- Если бэкенд падает с ошибкой про столбец `owner`, база создана старой версией: удалите `data/app.db`.

**Дополнительные инструменты**

```bash
python -m backend.ocr путь/к/документу.jpg --out data/ocr
```

```bash
streamlit run ui/ocr_check.py
```

```bash
python -m backend.bench путь/к/документу.jpg
```

Первая команда сохраняет распознанный текст и JSON со строками и рамками, вторая открывает отладочную страницу OCR,
третья замеряет время обработки (с прогревом и без, флаг `--no-warmup`).

## Работа офлайн

1. Один раз с интернетом скачайте модели: `python -m backend.warmup`.
2. Дальше запускайте бэкенд с `OFFLINE=1`: библиотеки не ходят в сеть и берут модели из кэша.
3. Страница тоже не требует сети: шрифты встроены, сбор статистики Streamlit отключён в `.streamlit/config.toml`.

В Docker всё это настроено по умолчанию.

При старте сервера модели прогреваются в фоне (`backend/warmup.py`), поэтому первый пользователь не ждёт их загрузки.
Документы, отправленные во время прогрева, ждут в очереди и обрабатываются автоматически.

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Состояние сервера и готовность моделей (`ready`) |
| `POST` | `/documents` | Загрузка документа: файл, `doc_type`, `question`, `session_id`. Возвращает задачу |
| `GET` | `/jobs/{job_id}?session_id=…` | Статус и результат задачи (`queued` → `processing` → `done` / `error`) |
| `GET` | `/jobs?session_id=…` | Все задачи посетителя |
| `DELETE` | `/jobs?session_id=…` | Очистить историю посетителя |

Пример ответа на вопрос:

```json
{
  "status": "missing",
  "message": "Не хватает следующих сведений: Дата выдачи. Основание: пункты 3.1 Положения.",
  "sources": ["rule:3.1"],
  "answerable": true,
  "value": "missing_fields",
  "missing_fields": ["issue_date"]
}
```

## Настройки (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MAX_UPLOAD_MB` | `10` | Максимальный размер файла (держите равным `maxUploadSize` в `.streamlit/config.toml`) |
| `MAX_ACTIVE_JOBS` | `10` | Лимит незавершённых задач на посетителя |
| `MAX_PDF_PAGES` | `3` | Сколько страниц PDF растеризуется |
| `JOB_TTL_MINUTES` | `60` | Через сколько минут задачи и файлы удаляются |
| `CLEANUP_EVERY_MINUTES` | `5` | Период очистки |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG` показывает опросы `GET /jobs`) |
| `USE_HANDWRITING` | `0` локально, `1` в Docker | Включить TrOCR для рукописных строк |
| `OFFLINE` | не задано, `1` в Docker | Запретить библиотекам обращаться в сеть |
| `API_URL` | `http://127.0.0.1:8000` | Адрес бэкенда для UI |
| `UI_PORT`, `API_PORT` | `8501`, `8000` | Порты Docker Compose |
| `WITH_HANDWRITING` | `1` | Собирать Docker-образ с TrOCR и PyTorch |

## Качество и метрики

Качество измеряется официальным `evaluate.py` организаторов на открытом наборе (30 документов, 120 вопросов).
Порядок запуска стенда и описание отчёта: [docs/EVAL.md](docs/EVAL.md).

Данные организаторов кладутся в `data/open/` (папка не попадает в git):

```
data/open/
├── documents/              open-001.png, open-001.pdf, ...
├── documents.json
├── questions.json
└── reference_results.json
```

```bash
python tools/run_batch.py --mode ocr --source png
```

**Результаты на открытом наборе**

| Метрика | Baseline PNG | Baseline PDF | `results.json` в репозитории |
|---|---|---|---|
| Точность полей (`field_accuracy_macro`) | 78.2 % | 73.6 % | **77.8 %** |
| Точность ответов (`question_exact_match`) | — | — | **70.8 %** |
| Полностью верная проверка документа (`validation_exact_match`) | 13.3 % | 13.3 % | **13.3 %** |
| Уровень A: эталонные поля → правила | — | — | **100 %** |

Уровень A (`python tools/run_batch.py --mode gold`, проверено на текущем коде) подтверждает, что логика ответов безошибочна, когда поля распознаны верно; основной источник ошибок —
OCR. Отчёты baseline с разбором по полям: [baseline_png.md](baseline_png.md), [baseline_pdf.md](baseline_pdf.md).

> После коммита `results.json` в код внесены исправления распознавания подписи и поля «Курс».
> Перед финальной сдачей перезапустите `run_batch` с `--no-cache` и обновите правый столбец (см. [docs/RELEASE.md](docs/RELEASE.md)).

```
└── .env.example
```
